How it works

The build is deliberately small. One rule shapes all of it.

The rule: the model reads, the code computes

1 · INGEST
Document in
PDF or DOCX, text extracted locally. Hashed.
2 · LLM · PAID
Read the clause
One call. Returns structured facts plus the sentence they came from.
3 · CODE · FREE
Compute the dates
Notice windows, roll-forward, states. Tested arithmetic.
4 · CODE · FREE
Sweep nightly
Re-derive everything against today. Open windows, escalate.
5 · SURFACE
Today
What must happen, why, and the clause behind it.

The expensive step happens once per document, ever. Everything that runs repeatedly — the nightly sweep, the recalculation, the escalation — is ordinary arithmetic and costs nothing. That is what keeps the running cost flat as the matter count grows.

What keeps the bill down

✓ Content-hash cache. The same document is never read twice, however many times it is uploaded.
✓ Structured output. The model returns a fixed schema, so there is no parse-and-retry loop burning tokens.
✓ Clause targeting. Only the relevant sections are sent, not the whole 60-page agreement.
✓ A hard monthly cap. Extraction stops at the ceiling and queues rather than overspending silently.
⚠ Scans still cost more. OCR quality drives confidence down and review effort up — the Ashfield document is the example.

Why this is the first thing to build

The full agent workspace — drafting, redlining, chat, connectors — is a large build with a diffuse benefit. Missing a notice deadline is a specific, expensive, insurable failure that lawyers already worry about. It needs no chat interface and no integrations to be useful on day one: a contract, a date, and arithmetic nobody has to trust a model to perform.
